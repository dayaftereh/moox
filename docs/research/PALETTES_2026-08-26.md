# External MOO2 palettes - extraction checkpoint 2026-08-26

The official MOO2 1.31 reference contains the known external palette sets in `FONTS.LBX` and `IFONTS.LBX`.

Public format documentation identifies:

- `FONTS.LBX` block 0 as font data, blocks 1..13 as external palettes,
- `IFONTS.LBX` block 0 as font data, blocks 1..4 as external palettes,
- the first 1,024 bytes of each palette block as 256 four-byte DAC-RGB entries,
- additional data after byte 1,023, described as containing cursor-related data that is not yet decoded.

Reference: https://masteroforion2.blogspot.com/2008/04/moo2-graphics.html

## Local extraction

`moox-analyze palettes` exports all 17 known palettes to:

```text
reference/original/palettes/
```

For every palette it creates:

- a JSON file with all 256 indices, raw marker/DAC values and converted 8-bit RGB,
- a 16x16 color-swatch PNG,
- a manifest entry containing archive/block/hash provenance,
- block/palette/tail byte counts and tail SHA-256.

All 17 local blocks are 12,544 bytes:

- 1,024 palette bytes,
- 11,520 unresolved tail bytes.

The original/private output is ignored by Git.

## External/mixed palette rendering

The single-image command now accepts an explicit palette context:

```powershell
out\moox-analyze-windows-amd64.exe image `
  -out reference\extracted\bldg0_block0_fonts002.png `
  -palette-file C:\ASH\Temp\mastori2\FONTS.LBX `
  -palette-block 2 `
  C:\ASH\Temp\mastori2\BLDG0.LBX 0
```

The public format description explicitly identifies this mapping for `BLDG0.LBX` block 0. The local test decodes it as a 640x480 frame with zero missing palette indices.

For mixed palettes, the external palette is applied only to color indices that are not already supplied by the graphic's internal palette. Internal colors therefore retain precedence.
