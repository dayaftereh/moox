# MOO2 1.31 ruleset

This directory is the normalized behavioral reference for the official Master of Orion II 1.31 target.

## Verification levels

Normalized values intentionally distinguish where they came from:

- `original-observed` - read directly from the local 1.31 data set and tied to an archive/block/hash/offset.
- `secondary-reference` - documented standard-game value cross-checked against a public reference, but not yet independently located in the original binary/data or measured in a controlled original-game experiment.
- Race Designer Pick costs are now directly sourced from `RACESTUF.LBX` block 6 and carry per-option source offsets.
- name provenance records where the original name was observed, while visible text itself lives in a language file; effect verification explains where exact formulas still need parity tests.

This distinction is important: MOOX should become exact by progressively replacing assumptions/secondary facts with reproducible original-game observations, not by hiding uncertainty.

## `race_traits.json`

Current normalized Race Designer baseline:

- schema version 2,
- 10 starting Picks,
- max 10 negative Picks,
- 11 groups,
- 53 selectable options,
- 1 required government selection (Dictatorship default),
- stable machine IDs and translation keys,
- numeric values for simple growth/economy/combat modifiers,
- special-ability IDs,
- known mutual exclusions,
- name source offsets into `RACESTUF.LBX` English block 0,
- Pick costs directly read from `RACESTUF.LBX` block 6 with per-option offsets,
- no embedded runtime display names or descriptions.

The file plus English language keys are generated by:

```powershell
out\moox-analyze-windows-amd64.exe normalize race-traits `
  -out data\rulesets\moo2-1.31\race_traits.json `
  -languages-dir data\languages `
  C:\ASH\Temp\mastori2
```

The Go loaders in `internal/ruleset` and `internal/i18n` validate the committed files during `go test ./...`.

## `assets.json`

The semantic asset catalog is tracked separately from original artwork. It currently contains 141 records: a verified race mapping layer, a small evidence-backed UI slice, and 48 original-executable-derived building colony sets:

- 13 preset-race portraits,
- 1 custom-race portrait,
- 52 farmer/worker/scientist/marine role icons,
- 13 generic race-icon keys kept explicitly pending until a universal source variant is proven.
- 13 selected UI/production references from independently revalidated render mappings,
- 1 directly documented building anchor: Alien Management Center -> BLDG0.LBX block 0,`r`n- 48 confirmed `building.<id>.colony` sets with 36 original-position variants each (1,728 references total).

Confirmed references include the original archive, block, frame, dimensions and block SHA-256. No original image bytes are stored in this directory.

Generate it with:

```powershell
out\moox-analyze-windows-amd64.exe normalize assets `
  -out data\rulesets\moo2-1.31\assets.json `
  -races data\rulesets\moo2-1.31\races.json `
  C:\ASH\Temp\mastori2
```

`go test ./...` loads the committed catalog and validates its portrait/icon keys against `races.json`.
## `buildings.json`

The 48 standard colony buildings are normalized into stable IDs and translation keys.

Name provenance is original 1.31 data:

- 46 names are exact `HELP.LBX` block 0 record headings,
- `Pollution Processor` and `Artificial Planet` are sourced from English `TECHNAME.LBX` block 0 because they are not present as HELP headings,
- `Pollution Processor` occurs twice in that TECHNAME block; this is recorded explicitly in `name_verification` rather than hidden.

Production IDs 1..48 and their technology IDs are now read directly from the original `Orion2.exe` 1.31 `_buildings` table (LE object 2, offset `0x6B3D`, 49 records x 19 bytes with record 0 as the dummy entry). `N_Bldgs_` independently confirms that normal gameplay iterates building IDs 1 through 48.

Technology links are now cross-checked against the original 203-entry TECHNAME.LBX technology sequence:

- 46 original building-table records reference technologies whose original names exactly match the building names,
- `Hydroponic Farms` is original building ID 21 -> original technology 87 `Hydroponic Farm` and is marked as a singular-name alias,
- original building ID 48 points directly to original technology 16 `Planet Construction`; the table relation is original-observed, while the display-name interpretation `Artificial Planet` remains the one identity link not encoded directly in the technology name.

All 48 standard buildings now carry a confirmed `building.<id>.colony` semantic asset key. The mapping is derived directly from the original 1.31 executable: `(building_id-1)/10` selects `BLDG0..4`, the remainder selects a 36-block building group, and the original 6x6 serpentine coordinate function selects the effective frame. The extra `BLDG4` group at blocks 288..323 remains deliberately unassigned because standard IDs 1..48 never reach it.

Generate it with:

```powershell
out\moox-analyze-windows-amd64.exe normalize buildings `
  -out data\rulesets\moo2-1.31\buildings.json `
  -languages-dir data\languages `
  C:\ASH\Temp\mastori2
```
## `technologies.json`

The original English `TECHNAME.LBX` block 0 contains a directly identifiable 203-entry concrete technology sequence. It begins immediately after `No Tech` with `Achilles Targeting Unit` and ends with `Zortrium Armor`; the next string is `Biology`, beginning another name section.

`technologies.json` preserves that original ordering as `technology_id` 1..203. Stable runtime IDs and language keys are derived from the original names, while every name records its exact source offset in the original block.

Generate it with:

```powershell
out\moox-analyze-windows-amd64.exe normalize technologies `
  -out data\rulesets\moo2-1.31\technologies.json `
  -languages-dir data\languages `
  C:\ASH\Temp\mastori2
```

This identity layer intentionally does not yet claim research field, research cost or exact effect formulas; those are separate decoding tasks.
